## Import and reuse

- Import formulas run at load time, not continuously after Cargo edits.
- Execution requires a stable `--id-column`; use `--source` to namespace IDs.
- Reimports read existing Cargo rows, skip identical inputs, and reject changes rather than overwrite results.
- Checkpoints stop ambiguous retries. Read-check-create is not an atomic server upsert; concurrent imports from separate machines remain a limitation.
- `--reuse-existing` can bypass mapped enrichment calls only when exported scalar fields cover every downstream output needed. AI answers and arbitrary nested provider JSON are not reused automatically.
- This reuse guard has local tests; live provider parity still needs a pilot.

Provider actions only: **0.5 credits per row** if every mapped enrichment runs. This excludes workflow execution and LLM costs. Provider subtotal for a 20-row pilot: **10 credits**.

AI usage depends on the authenticated LLM connector and its billing configuration. Cargo may meter Anthropic usage; verify the destination connector and do not assume AI is outside Cargo credits. Workflow nodes also incur execution charges (the installed Cargo guidance states 0.01 credits per node execution). These are additional to the provider-action subtotal.

## Run it

```bash
cargo-ai project info  # declared resources
cargo-ai project plan  # review the deployment diff
cargo-ai project deploy  # only after reviewing and approving the plan
cargo-ai storage model list   # copy the uuid of clay_demo_companies
node scripts/clay-demo-companies/load-rows.ts --csv <clay-export.csv> --model-uuid <uuid> --id-column <stable-source-column> --source <source-name> --execute
# run the play once on the pilot rows from the app, then:
node <path-to-clay-to-cargo>/src/cli.ts parity --schema <schema.json> --clay <clay-export.csv> --cargo <cargo-export.csv>
```

Enable the play only after the parity numbers are good enough for you. That call is yours, not the tool's.
