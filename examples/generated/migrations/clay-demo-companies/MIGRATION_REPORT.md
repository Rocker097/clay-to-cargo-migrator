## Provider swaps

Clay used providers Cargo does not run for these jobs. Each was swapped for the action Cargo's own clay-to-cargo recipe names. Fill rates can differ, which is what the parity check measures.

- **Enrich company**: `cpj-enrich-company` -> `linkedin.enrichCompanyFromDomain`

## Cost

| Column | Cargo action | Credits per call |
|---|---|---|
| Enrich company | `linkedin.enrichCompanyFromDomain` | 0.5 |

Provider actions only: **0.5 credits per row** if every mapped enrichment runs. This excludes workflow execution and LLM costs. Provider subtotal for a 3-row pilot: **1.5 credits**; provider subtotal for the full 3-row CSV: **1.5 credits**.

AI usage depends on the authenticated LLM connector and its billing configuration. Cargo may meter Anthropic usage; verify the destination connector and do not assume AI is outside Cargo credits. Workflow nodes also incur execution charges (the installed Cargo guidance states 0.01 credits per node execution). These are additional to the provider-action subtotal.

Prices from Cargo's credits table (cargo-gtm/references/credits-cost-table.md). Do not compare them to Clay credits: different units. Compare what the same sample cost end to end on each side.

## Run it

```bash
cargo-ai project info  # declared resources
cargo-ai project plan  # review the deployment diff
cargo-ai project deploy  # only after reviewing and approving the plan
cargo-ai storage model list   # copy the uuid of clay_demo_companies
npx tsx scripts/clay-demo-companies/load-rows.ts --csv <clay-export.csv> --model-uuid <uuid> --execute
# run the play once on the pilot rows from the app, then:
npx tsx <path-to-clay-to-cargo>/src/cli.ts parity --schema <schema.json> --clay <clay-export.csv> --cargo <cargo-export.csv>
```

Enable the play only after the parity numbers are good enough for you. That call is yours, not the tool's.
